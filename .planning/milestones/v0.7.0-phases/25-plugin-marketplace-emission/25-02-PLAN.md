Add two new functions to lib/plugin-helpers.sh (append after existing functions). POSIX 3.2+. No associative arrays, no mapfile.

FUNCTION 1: plugin_build_marketplace_json(target, mkt_name, version, owner_name):
  - Call detect_github_source "$target" to get owner_repo (or empty on failure)
  - If owner_repo non-empty: resolve SHA via `git -C "$target" rev-parse HEAD 2>/dev/null`; build source object with source="github", repo="$owner_repo", ref (from `git -C "$target" rev-parse --abbrev-ref HEAD 2>/dev/null || echo main`), sha (per D-16: write both ref and sha)
  - If owner_repo empty: source object with source="local" only
  - Build marketplace JSON via jq with --arg mkt_name, --arg version, --arg owner_name, --argjson source_obj. Shape from RESEARCH.md §marketplace.json complete schema: {name: $mkt_name, owner: {name: $owner_name}, plugins: [{name: $mkt_name, source: $source_obj, version: $version}]}
  - Validate with `printf '%s' "$MKT_JSON" | jq empty 2>/dev/null || { echo "✗ jq produced invalid JSON for marketplace.json" >&2; return 1; }`
  - Print resulting JSON to stdout (caller validates with validate_marketplace_json, then mutate_write)

FUNCTION 2: plugin_wire_settings(settings_file, mkt_name, mkt_source_obj, plugin_key, do_enable):
  - Read existing settings: CURRENT="$(cat "$settings_file" 2>/dev/null || echo '{}')"
  - Build extraKnownMarketplaces merge using RESEARCH.md Pattern 2's jq expression: `.extraKnownMarketplaces = (.extraKnownMarketplaces // {}) | .extraKnownMarketplaces[$name] = {"source": $src}` where $name=$mkt_name and $src=$mkt_source_obj (as jq object)
  - If do_enable=1: also merge enabledPlugins: `.enabledPlugins = (.enabledPlugins // {}) | .enabledPlugins[$key] = true` where $key=$plugin_key (shape: "plugin-name@marketplace-name" per RESEARCH.md §extraKnownMarketplaces)
  - Both merges can be chained in a single jq call or two sequential calls. Either is acceptable — prefer a single jq call for atomicity.
  - Run `printf '%s' "$UPDATED" | jq empty` before mutate_write
  - Call mutate_write "$settings_file" "$UPDATED"
  - D-15 idempotency is guaranteed by the keyed-object pattern: re-running sets the same key to the same value (sha updates in place, no duplication possible)

The mkt_source_obj parameter is a jq-encoded JSON object string passed from emit-plugin.sh (not a shell variable with spaces). Use `--argjson src "$mkt_source_obj"` in the jq call.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| --marketplace name (user-supplied via CLI flag or env var) → reserved_name_check | Marketplace name is user-controlled input; must be validated before use |
| git remote URL → detect_github_source → settings.json | Remote URL is auto-detected; must only accept github.com URLs (SSH + HTTPS forms) |
| emitted marketplace.json content → mutate_write | Manifest content built from harness; must pass secret_scan before write |
| settings.json merge → mutate_write | Settings.json is a critical project file; writes must be idempotent and backup-protected |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-07 | Spoofing | --marketplace name in emit-plugin.sh --marketplace path | mitigate | reserved_name_check called before ANY write (D-07); exit 2 on exact-match or impersonation-prefix match; test PLUG-02-reserved verifies |
| T-25-08 | Info Disclosure | marketplace.json env/source fields | mitigate | secret_scan on full MKT_JSON before mutate_write (D-08); exits 2 before any file write on credential pattern match |
| T-25-09 | Tampering | settings.json keyed-object merge | mitigate | jq keyed-object idempotent pattern (D-15); re-run updates in place, never appends duplicate; test PLUG-03-idem verifies |
| T-25-10 | Tampering | extraKnownMarketplaces array vs object | mitigate | jq expression `.extraKnownMarketplaces = (.extraKnownMarketplaces // {})` initializes as object; pattern confirmed from RESEARCH.md live test; Pitfall 3 documents this anti-pattern explicitly |
| T-25-11 | Tampering | git remote URL injection into marketplace.json source | accept | detect_github_source uses a case statement that only accepts github.com SSH/HTTPS forms; other remotes fall back to source="local" — no arbitrary URL injection possible |
| T-25-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan |
</threat_model>
