   b. Read known fields from schema: KNOWN_FIELDS="$(jq -r '.skill_frontmatter | keys[]' "$SCHEMA_FILE" 2>/dev/null)"
   c. For each top-level key in the frontmatter (lines matching `^[a-zA-Z]`):

   d. Detect object-typed fields using the awk two-line lookahead pattern (Pattern 1 from RESEARCH):
      - Inline object: line matches `^fieldname: *{` → OBJECT detected
      - Block mapping: key line with empty value followed by indented `  word:` line → OBJECT detected (the lookahead: prev_key set when value is empty; next line matches `^[[:space:]]+[a-zA-Z_-]+:` → emit OBJECT_FIELD:prev_key)

   e. Run OBJECT detection via a while loop reading the frontmatter block with printf. Use a POSIX-compatible approach: write the awk output to a temp file to avoid subshell FAIL counter issue.

3. Use printf '%s\n' "$FM_BLOCK" and `while IFS= read -r line` for POSIX 3.2+ compliance. No associative arrays, no mapfile, no local -n.

5. Similarly `allowed-tools`, `arguments`, `paths` accept "array-or-space-string" — same rule.

POSIX considerations:
- Use a tempfile for the while-loop err() calls (same pattern as the existing POL-05b tempfile at line ~260 in audit-setup.sh). The err() function updates $FAIL in the main shell; a subshell while loop cannot propagate the increment.
- Pattern: SCHM01_ERRS="$(mktemp)"; write errors to SCHM01_ERRS inside the subshell; read them back in the main shell and call err() on each.
- shellcheck: use `# shellcheck disable=SC2155` where needed for combined declaration+assignment (var="$(...)") per the project CI gate.
