<objective>
Wave 3: Implement SCHM-05 (--json machine-readable output) in scripts/audit-setup.sh and wire --json flag in cli/conjure.

Purpose: SCHM-05 adds a JSON output mode to `conjure audit --json`. When CONJURE_JSON=1, audit-setup.sh emits ONLY a single JSON object to stdout — all human-readable text is routed to stderr. The JSON shape {schema_version, status, checks, summary} is the load-bearing contract for Phase 29 `conjure workspace audit` aggregation. Stable check IDs (SCHM-01-skill-field, SCHM-01-skill-unknown, SCHM-02-disablebypass, SCHM-STALE) make the output deterministically parseable. Exit codes are preserved: exit 2 on fail, exit 1 on warn-only, exit 0 on pass — same as non-JSON mode.

Wave 3 depends on Wave 1 (SCHM-01/02 audit checks must exist so their results appear in the JSON output). The `depends_on: ["27-01", "27-02"]` frontmatter also waits on Wave 2 so the full schema surface is settled before --json serialization; 27-02's check.sh edits are in different files and do not conflict with this plan's audit-setup.sh changes.
</objective>

STEP 1 — After arg parsing vars (after `TARGET="${1:-$(pwd)}"` and before `cd "$TARGET"`), add:

STEP 2 — Add json_check() helper function alongside note()/ok()/warn()/err():
  json_check() {
    # json_check <id> <severity> <message>
    # Appends a check record to CHECKS_JSONL when JSON_MODE=1.
    local _jc_id="$1" _jc_sev="$2" _jc_msg="$3"
    [ "$JSON_MODE" != "1" ] && return 0
    jq -cn \
      --arg id "$_jc_id" \
      --arg severity "$_jc_sev" \
      --arg message "$_jc_msg" \
      '{id: $id, severity: $severity, message: $message}' \
      >> "$CHECKS_JSONL"
  }

STEP 3 — Route ALL human-readable stdout to stderr in JSON mode. This is the critical pitfall (Pitfall 2 from RESEARCH). Audit-setup.sh has multiple `echo` calls that go to stdout:
  - Line 29: `echo` (blank line)
  - Line 30: `echo "Auditing .claude/ setup in: $TARGET"`
  - Line 31: `echo` (blank line)
  - Line 289: `echo` (blank line before summary)
  - Line 290: `echo "─────..."`
  - Line 291: `echo "PASS: $PASS    WARN: ..."`
  - Line 292: `echo "─────..."`
  Plus all echo/printf calls inside the --cost section (lines 293-358) and --retire-list section (lines 361-405).

For each of these, wrap with: `[ "$JSON_MODE" != "1" ] && echo "..."` OR redirect to stderr: `echo "..." >&2` when JSON_MODE=1.

Most practical approach: define a `human()` output function that routes to stdout in normal mode and to stderr in JSON mode:
  human() { [ "$JSON_MODE" = "1" ] && printf '%s\n' "$1" >&2 || printf '%s\n' "$1"; }
Then replace all bare `echo "..."` (human-readable output) calls with `human "..."`. Exception: the JSON object emitted at the end goes to stdout directly via jq.

STEP 4 — Feed SCHM-01 and SCHM-02 results into the JSON accumulator. In the SCHM-01 section (Wave 1 code), after each warn() / err() call, add the corresponding json_check() call:

  Note: json_check() is a no-op when JSON_MODE=0, so the adds have zero impact on normal mode.

STEP 5 — Add SCHM-STALE staleness check (lives in audit, not check). Place it in the SCHM section (after SCHM-01/02):
  SCHEMA_GENERATED="$(jq -r '.generated // empty' "$SCHEMA_FILE" 2>/dev/null)"
  if [ -n "$SCHEMA_GENERATED" ]; then
    GEN_EPOCH=$(date -j -f "%Y-%m-%d" "$SCHEMA_GENERATED" "+%s" 2>/dev/null \

STEP 6 — At the END of audit-setup.sh, AFTER the cost/retire sections, BEFORE the existing `[ "$FAIL" -gt 0 ] && exit 2` gate, add JSON emission block:
  if [ "$JSON_MODE" = "1" ]; then
    _json_status="pass"
    [ "$FAIL" -gt 0 ] && _json_status="fail"
    [ "$WARN" -gt 0 ] && [ "$_json_status" = "pass" ] && _json_status="warn"
    jq -cn \
      --arg schema_version "1" \
      --arg status "$_json_status" \
      --argjson summary "{\"pass\":$PASS,\"warn\":$WARN,\"fail\":$FAIL}" \
      --slurpfile checks "$CHECKS_JSONL" \
      '{schema_version: $schema_version, status: $status, checks: ($checks | flatten), summary: $summary}'
    # Exit codes are preserved: same as non-JSON mode
  fi

Then keep the existing exit gates UNCHANGED:

  [ "$WARN" -gt 0 ] && exit 1
  exit 0

Key invariants:
- The JSON object is emitted via jq -cn to stdout ONLY when JSON_MODE=1 — exactly one JSON object, nothing else.
- jq -cn --slurpfile reads CHECKS_JSONL: each line is a JSON object; --slurpfile wraps them in an array. Use `$checks | flatten` to get a flat array.
- The existing `[ "$WARN" -gt 0 ] && exit 1` gate at the bottom is the established contract — do NOT change it.
- The CONJURE_COST and CONJURE_RETIRE sections: in JSON_MODE=1, their echo/printf calls must be routed to stderr. Gate their output: `[ "$JSON_MODE" != "1" ] && { echo "── Cost Estimate ..."; ...; }` or use the human() helper for each output line.
- POSIX 3.2+: no associative arrays, no mapfile, no local -n in any new code.
- shellcheck: `jq -cn ... '{...}'` is fine; ensure `--arg` strings with variables are quoted correctly.
