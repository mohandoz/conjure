<objective>
Wave 1: Core shared library, regime data files, sandbox block emission (POL-01), permissions.deny mirror (POL-02), and CLI dispatch.

Purpose: Deliver the foundation that manages the sandbox block merge into .claude/settings.json and the enforcement-gap closure (every denyRead path mirrored into permissions.deny as Read()). lib/policy-helpers.sh extracts the shared jq logic. compliance/*/policy.sh files carry the per-regime deny-path data. scripts/emit-policy.sh is the emit worker that reads regime data, builds the sandbox JSON, validates it, and merges it into settings.json via mutate_write. The managed-settings.json and MDM artifact paths in emit-policy.sh are implemented as stubs in this plan — their full implementation is Wave 2 (Plan 02).

The idempotency guarantee is non-negotiable: jq's `.*` operator replaces arrays rather than concatenating them. The merge_sandbox_block function MUST use `def array_merge(a;b): (a // []) + (b // []) | unique;` for denyRead, denyWrite, allowWrite, allowRead, allowedDomains, and excludedCommands arrays (per RESEARCH.md Pattern 1 and Pitfall 3). Re-running emit-policy on the same target must produce an identical settings.json.

The permissions.deny double-slash rule (RESEARCH.md Pattern 2, Pitfall 2): sandbox denyRead paths starting with `/` must become `Read(//<path>)` in permissions.deny — a single-slash Read entry for an absolute path is project-root-relative, not absolute, and would silently misclassify the deny.

Output: lib/policy-helpers.sh, compliance/*/policy.sh (×4), scripts/emit-policy.sh, modified cli/conjure. Tests POL-01, POL-01-idem, POL-02, POL-dryrun go green.
</objective>

1. secret_scan(content, label):

The regex covers: sk-ant-[A-Za-z0-9_-]{10,}, sk-[A-Za-z0-9_-]{32,}, AKIA[0-9A-Z]{16} (AWS access key), and quoted assignments for api_key/secret_key/private_key/access_token/auth_token with values of 6+ chars. Caller must: secret_scan "$CONTENT" "managed-settings.json" || exit 2.

2. validate_sandbox_json(content):
   Three jq -e checks accumulating into an errors counter (mirror validate_plugin_json pattern from lib/plugin-helpers.sh):
   - Check (.enabled | type) == "boolean": error "sandbox: 'enabled' must be a boolean"
   - Check (.filesystem.denyRead | type) == "array": error "sandbox: 'filesystem.denyRead' must be an array"
   - Check (.network.allowedDomains | type) == "array": error "sandbox: 'network.allowedDomains' must be an array"
   Return 1 if errors > 0, else return 0. Each check uses: `if ! printf '%s' "$content" | jq -e '...' >/dev/null 2>&1; then echo "✗ ..." >&2; errors=$((errors + 1)); fi`
   Caller must: validate_sandbox_json "$SANDBOX_JSON" || exit 2.

3. build_sandbox_block(deny_read_json, deny_write_json):
   Arguments: JSON arrays (strings). Uses jq -n with --argjson to build the sandbox object. Shape from RESEARCH.md Code Examples §build_sandbox_block:
     jq -n --argjson deny_read "$deny_read_json" --argjson deny_write "$deny_write_json" '{enabled:true, failIfUnavailable:true, allowUnsandboxedCommands:false, filesystem:{denyRead:$deny_read, denyWrite:$deny_write}, network:{allowedDomains:[]}}'
   Print result to stdout. Caller captures: SANDBOX_JSON="$(build_sandbox_block "$DENY_READ_JSON" "$DENY_WRITE_JSON")"

4. build_deny_read_entries(deny_read_json):
   Argument: JSON array of denyRead paths. Uses printf + jq -r '.[]' to iterate (POSIX-safe, no mapfile). For each path, apply prefix convention from RESEARCH.md Pattern 2:
     case "$path" in
       ~/*)  printf 'Read(%s)\n' "$path" ;;         # home-relative: keep as-is
       /*)   printf 'Read(/%s)\n' "$path" ;;        # absolute: prepend extra / (double-slash)
       ./*)  printf 'Read(%s)\n' "${path#.}" ;;     # project-relative: strip leading dot
       *)    printf 'Read(%s)\n' "$path" ;;         # bare: pass through
     esac
   Prints one Read(<path>) entry per line to stdout. Caller captures to build the permissions.deny array.

5. merge_sandbox_block(settings_file, sandbox_json):
   Arguments: path to existing settings.json (or /dev/null if absent), the new sandbox JSON string.
   Implementation from RESEARCH.md Pattern 1 (the exact array_merge idiom):
     - Read existing file content: CURRENT="$(cat "$settings_file" 2>/dev/null || printf '{}')"
     - jq merge with def array_merge(a;b): (a // []) + (b // []) | unique; for all array fields:
       .sandbox.filesystem.denyRead, .sandbox.filesystem.denyWrite, .sandbox.filesystem.allowWrite,
       .sandbox.filesystem.allowRead, .sandbox.network.allowedDomains, .sandbox.excludedCommands
     - Scalar fields (enabled, failIfUnavailable, allowUnsandboxedCommands) use new value from $new (overwrites — new value wins, same value on re-run so idempotent)
     - jq-empty-check: `printf '%s' "$UPDATED" | jq empty 2>/dev/null || { echo "✗ jq produced invalid JSON for settings.json (sandbox merge)" >&2; return 1; }`
     - Call mutate_write "$settings_file" "$UPDATED"
   Note: callers must also call build_deny_read_entries and add the resulting Read() entries to the .permissions.deny array using the same array_merge pattern in a separate jq step, then call mutate_write again. Alternatively, merge_sandbox_block can accept a third argument for the deny_read_entries array and merge them in a single jq pass — use whichever approach is cleaner and shellcheck-passes.
