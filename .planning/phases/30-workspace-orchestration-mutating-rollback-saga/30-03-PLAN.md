<objective>
Wave 3: `workspace adopt` saga orchestrator — the all-snapshot-before-any-apply state machine.

ws_do_adopt implements the two-phase saga: PHASE A snapshots ALL repos (writing state atomically before+after each op) before PHASE B applies to ANY. The state machine schema, disk estimate gate, --tag filter, --dry-run zero-write contract, and traversal re-check per repo are all implemented here.

This is the highest-complexity implementation in Phase 30. The saga invariant (all snapshotted before first applied) is the primary correctness property; the SIGKILL durability comes from the atomic state writes delivered in Wave 1.

Purpose: WS-06 — delivers the saga contract that Wave 4 --rollback restores from.

Output: ws_do_adopt + adopt dispatch in scripts/workspace.sh; ws_sha_of helper in lib/workspace.sh.
</objective>

    ws_do_adopt <manifest_path> <manifest_dir> <tag_filter> <allow_large> <dry_run> <yes>:
    - Non-TTY consent gate: if YES=0 and not TTY and DRY_RUN=0 → exit 2
    - Resolve manifest_root (pwd -P) and workspace state path: "$manifest_dir/.conjure-workspace-state.json"
    - Build repo list (tag_filter: if non-empty, only repos where jq -e ".tags[] | select(. == \"$tag_filter\")" matches)
    - PREFLIGHT / disk estimate: for each filtered repo: du -sk repo_abs (awk '{print $1}'); sum KiB; if sum > 2097152 and ALLOW_LARGE=0: warn + exit 2; if ALLOW_LARGE=1: warn and proceed
    - DRY_RUN: if DRY_RUN=1: print plan (repos + estimated size); print [dry-run] would snapshot N repos; return 0 (state file must NOT be written; snapshots must NOT be taken)
    - STATE INIT: workspace_state_write state_path with full initial object: {run_id (date-based unique), started (ISO timestamp), phase:"snapshot", repos:[{name,snapshot_ref:"",sha256_pre_ref:"",status:"pending"} for each filtered repo]}
    - PHASE A: for each filtered repo (in order):
      - CR-02 traversal re-check before snapshot (exit 2 on out-of-bounds)
      - PRE-WRITE: workspace_state_write to update repo status to "snapshotting" — this is the in-progress sentinel; written BEFORE snapshot_create is called (SIGKILL durability: if killed here, state shows "snapshotting" + empty snapshot_ref — ws_do_rollback treats this as never-mutated → skip with note)
      - snapshot_create call (TWO-ARG API): backup_root="$repo_abs/.conjure-adopt-backups"; snapshot_create "$repo_abs" "$backup_root"; snap_ref="$CONJURE_SNAPSHOT_PATH" — capture the snapshot path from the CONJURE_SNAPSHOT_PATH env variable (snapshot_create sets it; its stdout is not useful)
      - Compute per-file sha256 hash file: mktemp file outside repo; cd to repo_abs; find . -type f -not -path './.git/*' | sort | while read f; printf '%s  %s\n' "$(ws_sha_of "$f")" "$f"; done > "$hash_file"
      - POST-WRITE: workspace_state_write to update repo entry: snapshot_ref="$snap_ref", sha256_pre_ref="$hash_file_path", status="snapshotted" (status upgraded from "snapshotting" to "snapshotted" only after snapshot_create returns 0)
      - On snapshot_create failure: update repo status to "failed"; set PHASE_A_FAILED=1; break PHASE A loop
    - PHASE B: if PHASE_A_FAILED: echo "✗ snapshot phase failed — not applying any repo" >&2; exit 2
      - workspace_state_write: update top-level phase to "apply"
      - For each filtered repo (status=snapshotted only):
        - CR-02 traversal re-check before apply (exit 2 on out-of-bounds)
        - Pass CONJURE_ADOPT_REUSE_SNAPSHOT=1 in the subprocess environment: CONJURE_ADOPT_REUSE_SNAPSHOT=1 bash "$CONJURE_HOME/cli/conjure" adopt "$repo_abs" — this tells adopt.sh to skip its internal snapshot_guarded (workspace already snapshotted every repo in PHASE A; prevents double-snapshot disk overhead)
        - repo_rc=$?; if rc=0: workspace_state_write repo status="applied"; else: workspace_state_write repo status="failed"; STOP-ON-FAIL: exit 2 after recording failure
    - PHASE DONE: workspace_state_write: phase="done"
    - Print aggregate report
    - exit codes: 0=all applied; 2=any failure (stop-on-fail); never exit 1 for ws_do_adopt hard errors
