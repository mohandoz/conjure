POL-05b CHECK — denyRead path with no matching Read() in permissions.deny:
  Gate: [ -n "$_pol_regime" ] && [ -f ".claude/settings.json" ] && command -v jq >/dev/null 2>&1
  Iterate denyRead paths and check for Read() mirror per RESEARCH.md Pattern 6 §POL-05b. Use a while-loop with process substitution for POSIX compatibility. Critical: the grep for Read() entries must handle the double-slash rule — for a denyRead path of /etc/passwd the permissions.deny entry is Read(//etc/passwd) (double-slash). Use grep -F for literal string matching:
    _deny_paths="$(jq -r '.sandbox.filesystem.denyRead // [] | .[]' .claude/settings.json 2>/dev/null)"
    _perm_deny="$(jq -r '.permissions.deny // [] | .[]' .claude/settings.json 2>/dev/null)"
    printf '%s\n' "$_deny_paths" | while IFS= read -r _dpath; do
      [ -z "$_dpath" ] && continue
      if ! printf '%s\n' "$_perm_deny" | grep -qF "Read($_dpath)"; then
        err "[policy:$_pol_regime] denyRead path '$_dpath' has no matching Read($_dpath) in permissions.deny (POL-02 enforcement gap)"
      fi
    done
  Note on pipe subshell: the while loop runs in a subshell in POSIX bash; FAIL counter increments inside the subshell are lost. To propagate the failure, write error messages to a tempfile instead of calling err() directly:
    _pol_b_errs="$(mktemp)"
    ... write errors to _pol_b_errs ...
    if [ -s "$_pol_b_errs" ]; then
      while IFS= read -r _msg; do err "$_msg"; done < "$_pol_b_errs"
    fi
    rm -f "$_pol_b_errs"
  This pattern avoids the subshell FAIL counter loss and is POSIX-safe.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-26-14 | Tampering | POL-05b denyRead check: Read() entry exists but uses single-slash for absolute path (false negative) | mitigate | The POL-05b check uses grep -qF "Read($dpath)" — it checks for the path as-is (e.g., `Read(//etc/passwd)` for an absolute path). Since emit-policy.sh uses build_deny_read_entries which applies the double-slash rule, the Read() entry in permissions.deny will have the double slash. The POL-05b grep uses the original denyRead path (e.g., `/etc/passwd`) and checks for `Read(/etc/passwd)` — not the double-slash form. To catch mismatches, POL-05b should check BOTH `Read($dpath)` and the double-slash form. Accept as known limitation documented in audit output — the primary protection is the double-slash rule in build_deny_read_entries |
| T-26-15 | Tampering | POL-05a: overlay marker in CLAUDE.md but no jq on path (false negative, no audit) | mitigate | command -v jq check gates the audit block; if jq absent, note "jq not found — policy checks skipped" (advisory); do NOT silently skip without informing the user |
